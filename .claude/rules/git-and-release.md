# Git and release rules

## Commits

- Conventional Commits 1.0.0, in English: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `revert`, `style`, `chore`, `build`, `ci`. Optional scope (`feat(combat): ...`).
- Micro-commit per completed micro-task. Code, test and docs of the same change go in the same commit.
- Never use `--no-verify`. A failing hook points to a defect to fix.
- Never commit `.env`, PDFs, `references/`, `node_modules/`, `dist/`.

## Push and release

- Push to `main` only at the end of each task group in `PLAN.md`, with the group's asserts verified and `bun run ci` green.
- Each push creates a GitHub release through `bun run release` (see `docs/adrs/0002-release-format.md`): version bump, `CHANGELOG.md` regenerated by git-cliff, tag `vX.Y.Z`, notes = the version section of the changelog.
- Versions: `0.0.x` in Alpha (each push increments the patch), `0.1.x` in Beta, `1.0.0` at launch.

## CI/CD

- GitHub Actions: `ci.yml` runs `bun run ci` on push and PR; `deploy.yml` publishes the build to Vercel (alpha.lekzera.xyz) on push to `main`.
- The local gate stays mandatory: `bun run ci` before every push.

## Parallel work

- No worktrees unless the developer explicitly asks. Parallel agents touch distinct files; the coordinator (main session) integrates and commits.
- If there is a branch: rebase onto `main` before integrating; resolve conflicts by reading both sides, never discarding one.

## Destructive operations

- `git reset --hard`, `push --force`, deleting a branch or tag: only with the developer's explicit request.

## Releasing while agents work

- Parallel agents keep editing the working tree. Never run `git stash`, `git rebase --autostash` or any command that rewrites working files while they work: it reverts their uncommitted edits.
- Release from a scratchpad clone instead: `git clone <repo> <scratchpad>/relclone`, `git remote set-url origin https://github.com/AlexGalhardo/project-alpha.git`, `bun install --frozen-lockfile`, `bun node_modules/electron/install.js`, then `bun run release`. Bring the release commit back with `git fetch origin && git merge origin/main`.
- Each release attaches the web `.tar.gz`, the Windows exe, the Android APK (when `ANDROID_HOME` is set) and `checksums.txt`. Add a short "Highlights" paragraph at the top of the notes (`gh release edit`).
