# ADR 0002: GitHub release format

- Status: accepted
- Date: 2026-10-26

## Context

The developer requires one release per push, with the same quality as <https://github.com/AlexGalhardo/vukem/releases>. Analysis of `v0.32.0` and `v0.31.0` in that repository (via `gh release view`) and of its `.config/cliff.toml`:

- Title = tag (`v0.32.0`).
- Body = the version section of `CHANGELOG.md`, without the `## [x.y.z]` heading, grouped under `### Added`, `### Changed`, `### Fixed`, `### Security` (Keep a Changelog 1.1.0).
- Each line: `- **scope:** Message starting with a capital letter ([sha7](commit link))`.
- Generated by git-cliff from Conventional Commits; `docs`/`test`/`ci`/`build`/`chore`/`style` are omitted.
- Binary assets (GoReleaser, checksums, SBOM, cosign signature): specific to a Go CLI.

## Decision

- `cliff.toml` replicates the vukem template (lines, commit links, footer comparing versions).
- Deliberate difference: `docs` appears as a `### Documentation` group, because in the planning phases the documents are the main deliverable and without it the release would be empty.
- `bun run release [patch|minor|major]` (`scripts/release.ts`): requires branch `main` and a clean tree → `bun run ci` → version bump in `package.json` (the first release uses the current version, `0.0.1`) → `CHANGELOG.md` regenerated → commit `chore(release): vX.Y.Z` → annotated tag → `git push --follow-tags` → `gh release create` with the version notes.
- Release assets: none until a web build exists. From the PROTOTYPE phase on, attach `project-alpha-web-vX.Y.Z.zip` + `checksums.txt` (task in `PLAN.md`).
- Versioning: `0.0.x` Alpha, `0.1.x` Beta, `1.0.0` stable.

## Alternatives

- `release.yml` GitHub Actions workflow: dropped for now; the local script is the single path and runs the same CI gate.
- `release-please` / `semantic-release`: larger dependencies and a format different from vukem's.

## Consequences

- A commit without a releasable type (`feat`/`fix`/`perf`/`refactor`/`revert`/`docs`) since the last tag makes the script fail with a clear message.
- `CHANGELOG.md` is never edited by hand; fixing a commit message fixes the changelog.
