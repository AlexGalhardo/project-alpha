## 1. Goal

Every player-facing string comes from typed dictionaries in English (default) and Brazilian Portuguese, with identical keys and placeholders, rendered only with glyphs present in the bitmap font atlases.

## 2. Non-goals

- Other languages, right-to-left scripts, voice.
- Text in `src/core` (the core emits ids).

## 3. Requirements

- R-1 `src/i18n/en.ts` is the source; `src/i18n/pt-BR.ts` is typed as `Strings` (same shape); missing or extra keys fail the type check (ADR 0009).
- R-2 Placeholders use `{name}` and are identical per key in both languages.
- R-3 `t(key, params?)` in the view returns a string; unknown keys never reach the screen (type error at build time).
- R-4 Key families: `ui.*`, `card.<id>.{name,short,text,flavour}`, `enemy.<id>.{name,lore}`, `hero.<class>.{name,role}`, `item.<id>.{name,text}`, `status.<id>.{name,text}`, `intent.<id>.text`, `node.<type>.name`, `event.*` (Alpha), `boss.bell_maw.epilogue`.
- R-5 Budgets (GDD §16.2): card/item rules ≤ 12 words; enemy lore 1–2 lines; boss epilogue 2–3 lines; card short name ≤ 58 px in `font.ui`.
- R-6 Default language: PT-BR if the browser language starts with `pt`, else English; switchable at any time, including mid-run and from pause.
- R-7 Every character used in both dictionaries exists in every font atlas that renders it (Art Bible §8).
- R-8 Numbers are formatted per language (`1,250` EN, `1.250` PT-BR) by a helper; game numbers in cards are integers.

## 4. Design

```typescript
// src/i18n/en.ts
export const en = { ui: { newRun: 'New run' /* … */ }, card: { shb_hack: { name: 'Hack', short: 'Hack', text: 'Deal {dmg} damage.' } } } as const;
export type Strings = DeepString<typeof en>;
// src/i18n/pt-BR.ts
export const ptBR: Strings = { /* same keys */ };
```

## 5. Acceptance criteria

- AC-1 Given a key added to `en.ts` only, then `bun run typecheck` fails.
- AC-2 Given every key, then the set of `{placeholders}` is equal in EN and PT-BR (unit test).
- AC-3 Given the glyph test, then every character of both dictionaries exists in the atlas of the font that renders it.
- AC-4 Given every `card.<id>.short`, then its width in `font.ui` metrics is ≤ 58 px.
- AC-5 Given a language switch mid-combat, then all visible text updates on the next frame and the run state is unchanged.
- AC-6 Given the card text budget, then no `card.*.text` exceeds 12 words (keyword tokens count as one word).

## 6. Edge cases

- Capitalised accents ("AÇÃO") need the line spacing of Art Bible §8.
- Plurals: use explicit keys (`ui.cardsLeft.one`, `.other`) with a tiny selector; no ICU library.
- Proper nouns (Ossuary, Bell-Maw) stay the same in both languages unless the GDD says otherwise.

## 7. Test strategy

- Type check (AC-1); unit tests for parity, placeholders, budgets, glyph coverage (AC-2..AC-6); human QA section 21.

## 8. Verification

```sh
bun run typecheck
bun test tests/unit/i18n.test.ts
```
